# 輕量樓宇資料與關注標色

## 已接入

| 資料 | 官方來源 | 用途與限制 |
|---|---|---|
| 建築輪廓、高度、層數、名稱 | [地政總署 Building](https://portal.csdi.gov.hk/csdi-webpage/dataset/landsd_rcd_1637211194312_35158) | 只取 Active；按視野分頁讀取，不按高度刪掉小型建築。輪廓包括塔樓、平台及其他結構，輪廓數不等於大廈數。 |
| 入伙紙日期、編號及用途 | 同一資料集的 BuildingRelateOPStructure、OPStructure、OP | 沿官方 CSUID 關聯鏈配對。樓齡按入伙紙日期計算，並非結構實際建成年份鑑定。多個日期時不猜單一年份；沒有日期便顯示未能確定。 |
| 曾發出的強制驗樓通知 | [屋宇署 MBIS](https://data.gov.hk/en-data/dataset/hk-bd-opendata-mbis-s30b-notice-1) | 2023-05 起累計發出紀錄；以 CSV／服務內明確的 CSUID 配對。 |
| 曾發出的修葺令 | [屋宇署 S26](https://data.gov.hk/en-data/dataset/hk-bd-opendata-s26-order-1) | 同上，不能稱為尚未遵從的命令或正在施工。多個 CSUID 可能共享同一樓座通知，不能把地圖輪廓數或各輪廓通知相加當全港總數。 |
| 已遵從／撤銷／被取代的驗樓通知 | [屋宇署 MBIS 處理紀錄](https://data.gov.hk/en-data/dataset/hk-bd-opendata-mbis-s30b-notice-2) | 2024-05 起累計，另列於資訊卡，不與發出量相減。 |
| 已遵從／撤銷／被取代的修葺令 | [屋宇署 S26 處理紀錄](https://data.gov.hk/en-data/dataset/hk-bd-opendata-s26-order-2) | 同上。 |

另找到 [屋宇署樓宇資料及樓齡紀錄](https://data.gov.hk/en-data/dataset/hk-bd-opendata-building-information)，有地址、用途、入伙紙日期。其數字樓座 ID 與地政資料不能在未驗證下直接當成同一識別碼；本版本以地政總署自己的入伙紙關聯作為顯示來源，沒有用最近鄰／地址猜配。

## 仍不能可靠回答的問題

- **正在大維修**：未找到覆蓋全港、逐座可查證施工中狀態的公開即時 API。[市建局維修成本參考](https://data.gov.hk/en-data/dataset/ura-ura-ura-rehab) 有實質完工年份，是歷史參考，不能當成施工中清單。
- **目前需要維修／命令未解除**：累計發出通知不等於現時未遵從。資訊卡另列已遵從／撤銷／被取代紀錄，但統計起點不同，不能直接相減得到可靠的現況。
- **50 年以上＝危險**：沒有這項推論。45–49 年只是此應用的「接近 50 年」分組，並非政府評級。
- 無配對紀錄不代表沒有命令、沒有問題或不需維修。

## 效能和真實性取捨

- 縮放 13.25–15 保留原有 OSM 輕量街廓，同時只傳送視野內有關注分類的官方樓宇，並用平面彩色輪廓標示。縮放 15 以上載入視野內完整官方 GeoJSON，成功後取代 OSM 建築，避免重疊。縮遠時沿用已載入的關注輪廓，不為擴大的視野重新抓取全部建築；移至新區域會嘗試載入該區關注輪廓。縮放 12–13.25 可保留已載入區域的彩色輪廓，但不擴大查詢範圍；更遠的視角不繪製輪廓。
- 沒有高度的官方輪廓仍顯示平面，不捏造樓高。高度為 TopHeight − BaseHeight，輕量模式在平面底圖上落地，並非精細地形模型。
- 官方資料只傳送目前視野及小量緩衝區；已載入範圍內放大不重新下載。伺服器分頁抓取全部結果、去除重複 OBJECTID，成功後才顯示完成數字，失敗保留 OSM 並提示。
- 圖層沒有近距離縮放截止；GeoJSON 可過度縮放。17.5 以上逐步限制最大傾角，到 20 轉為俯視，避免低空鏡頭穿入高樓導致裁切。
- 近景保留所有官方輪廓；遠景只渲染所選關注分類的彩色平面輪廓，普通建築沿用原有精簡 OSM 圖層。全部類別同時顯示時優先序為修葺令、驗樓、50+、45–49；單選樓齡時仍會包括有通知紀錄的舊樓。

## 更新及部署

```sh
npm run data:refresh
```

需要 Python 3，使用標準函式庫，從官方公開端點取得資料，不需要 API key。刷新會完整分頁讀取關聯及通知，所有來源成功後才原子替換 `data/building-registry.json`。資料保留在伺服器，不打包整份到瀏覽器。刷新後伺服器會在下一次查詢時讀入新快照；重新整理地圖即可看到新資料。

部署須包含 `data/`、`server/` 及 `dist/`。以 `npm run build && npm start` 執行；純靜態部署不能提供 `/api/buildings`。現有 3D Spatial Data 金鑰設定不變。

畫面顯示的是**擷取日期**，不等於官方資料的更新日期。修葺令／驗樓官方 LastUpdate 保存在快照 `updates`，入伙紙資料並非即時更新。建議每月手動刷新，未啟用自動排程。
